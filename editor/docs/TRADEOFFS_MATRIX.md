# TRADEOFFS_MATRIX.md — Rótulos Web v5.0
> Matriz de trade-offs para las decisiones técnicas más relevantes.

| # | Decisión Técnica | Beneficio Directo | Costo / Penalización | Alternativa Descartada | Razón del Rechazo |
|---|---|---|---|---|---|
| 1 | Módulos ES6 nativos sin bundler | Cero configuración de build; testabilidad inmediata por módulo | Sin tree-shaking; sin lazy-loading automático; todos los módulos se cargan en secuencia | Vite + Rollup como bundler | Agrega complejidad de build que rompe la filosofía "soberana" del proyecto; innecesario para el tamaño actual |
| 2 | `vitest@3.x` sobre Jest | ES modules nativos sin Babel; ejecución ultrarrápida (114 tests en <4s) | Dependencia de Node 18+ | Jest con `--experimental-vm-modules` | Configuración frágil; breaking changes frecuentes en soporte ESM de Jest |
| 3 | Middleware localhost-only | Protección total del filesystem del usuario | Sin acceso LAN/remoto posible | Autenticación JWT con sesiones | Agrega complejidad de auth innecesaria para una herramienta de escritorio local |
| 4 | Respaldos FIFO (15 archivos máx) | Protección contra pérdida de datos; rotación automática | Ocupa disco (máx ~15× tamaño del index.html) | Base de datos de versiones (SQLite) | Overhead de dependencia innecesaria; los archivos HTML son la fuente de verdad más directa |
| 5 | `ApiResponse<T>` sin TypeScript | Contratos consistentes sin migración de lenguaje | Sin type-checking en tiempo de compilación; solo JSDoc | Migrar a TypeScript completo | Requeriría configurar `tsc`, cambiar todos los archivos, y añadir paso de build — costo muy alto para beneficio bajo en un proyecto de esta escala |
| 6 | `app.js` original conservado como respaldo (no cargado) | Rollback de emergencia inmediato sin Git | Ocupa ~114 KB en disco; puede confundir a contribuidores | Eliminar `app.js` inmediatamente | Riesgo de que algún módulo tenga una regresión no detectada aún — la red de seguridad vale el espacio |
| 7 | Escritura atómica con `rename` | Garantía de que el archivo nunca queda en estado corrupto | Requiere sistema de archivos que soporte rename atómico (Linux/macOS sí; Windows puede fallar en cross-drive) | Write directo con backup previo | Probabilidad baja en uso local pero consecuencia catastrófica (pérdida de datos del usuario) |
| 8 | Catálogo `ERROR_CODES` centralizado | Un solo punto de cambio; facilita mapeo frontend | Requiere mantener sincronizados los códigos en el servidor | Mantener strings literales | Sin catálogo no hay contrato formal → los cambios de nombre son silenciosos y producen bugs difíciles de rastrear |
| 9 | `<dialog>` nativo para confirmaciones | Accesible, no bloquea hilo, estilizable con CSS | Requiere polyfill en navegadores muy antiguos (<2022) | `confirm()`/`prompt()` nativos | Bloquean el hilo principal; inaccesibles por teclado; no estilizables con la identidad de Memexicanísimos |
| 10 | GitHub Actions CI | Previene regresiones; gate automático antes de push | Requiere que el repo tenga Actions habilitado | Sin CI | Sin gate, cualquier commit puede romper los tests sin que el autor lo sepa |
| 11 | EventBus pub/sub tipado | Desacopla módulos de `window.editor` global | Requiere manejo de desuscripciones explícitas | Estado global reactivo (Redux/Zustand) | Complejidad y boilerplate excesivo para el tamaño de la UI |
| 12 | Web Workers (`fflate` + DOM) | Operaciones pesadas (ZIP, auditoría) a 60 FPS sin congelar la UI | Requiere serialización de mensajes por `postMessage` | Procesamiento síncrono en hilo principal | Congelaba el editor por 2-4 segundos en proyectos con activos grandes |
| 13 | Capas virtuales con `content-visibility` | Rendimiento fluido en árboles DOM de más de 200 nodos | Dependiente del soporte del navegador | Renderizado de todos los nodos en DOM | Caídas de frames perceptibles en scroll y drag-and-drop de componentes |
| 14 | Historial en `localStorage` (20 estados) | Recuperación de versiones de diseño tras recargar (F5) | Límite de 5MB por dominio en `localStorage` | Base de datos IndexedDB | `localStorage` es síncrono y suficiente para snapshots comprimidos de index.html |
| 15 | Gestión de proyectos en `~/RotulosProjects` | Múltiples proyectos locales limpios y portables | Carpetas estándar en disco sin BD | SQLite embebido para proyectos | Un directorio con `index.html` es legible, editable con cualquier IDE y portable sin migraciones |
| 16 | Publicación OAuth2 + GitHub Pages | Despliegue en 1-clic con HTTPS gratuito sin pedir tokens por consola | Requiere credenciales de App OAuth si se despliega en producción | Pedir Personal Access Token (PAT) manual | La experiencia de usuario de generar un PAT en github.com es frustrante para no-programadores |
| 17 | Variables CSS + data-theme para temas | Alternancia instantánea claro/oscuro sin recargar la página | Mantenimiento de colores en tokens CSS | Estilos CSS-in-JS (Tailwind/Styled-Components) | Requiere paso de compilación que rompe la arquitectura de Vanilla CSS soberana |
| 18 | Auditoría axe-core en Web Worker con fallback | Detección profunda de problemas WCAG 2.1 sin bloquear el lienzo | El script de axe añade ~580KB al directorio vendor | Auditoría solo en backend con Puppeteer | La auditoría en backend requiere navegador headless instalado; el worker funciona 100% en cliente |
